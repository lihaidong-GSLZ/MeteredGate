# Metered Gate 0.2.0 设计说明

本文档描述 Metered Gate `0.2.0` 的实际实现边界、运行时语义与兼容性约束。它面向后续维护者，不是玩家使用手册。

## 1. 设计目标

Metered Gate 是一个 `1×1` 的平面传送带物流节点。它要解决的问题不是限制瞬时带速，而是限制一个周期内**允许离开上游的离散货物数量**。

核心约束如下：

1. 每栋建筑独立设置周期长度与每周期配额；
2. 配额按周期重置，未使用额度不累积；
3. 物品离开上游、进入闸门时立即消耗配额；
4. 内部最多保存一个单位货物；
5. 多个输出采用简单轮询；
6. 建筑可架高，但高度边界由 Metered Gate 自己控制；
7. 保持 `0.1.0` 的模组 ID、原型 ID 和实体存档格式兼容。

## 2. 总体分层

### `MeteredGateMod`

模组入口，负责：

- 绑定 `config.json`；
- 注册 `MeteredGateData`；
- 在 `EarlyInit(...)` 中安装局部 Harmony 补丁；
- 在 `Dispose()` 中按固定 Harmony ID 卸载本模组补丁；
- 解除静态配置事件订阅。

`DataOnlyMod.Initialize(...)` 在游戏 `0.8.6c` 中不能覆盖，因此运行时补丁必须在 `EarlyInit(...)` 安装。

### `MeteredGateSettings`

负责读取新建筑默认值：

- `default_cycle_seconds`；
- `default_items_per_cycle`。

配置变化只更新之后新建建筑所使用的默认值，不修改已经建成并保存了独立参数的实体。

### `MeteredGateData`

负责从原版 Flat Conveyor 推导两个模板原型：

- Flat Balancer 对应的 `ZipperProto`；
- Flat Connector 对应的 `MiniZipperProto`。

两者在 `0.2.0` 中职责严格分离：

- **Balancer 只提供建造成本**；
- **Connector 只提供 `1×1` 布局、动态端口和图形模板**。

`MeteredGateData` 不负责物流运行状态，也不负责高度边界执行。

### `MeteredGateProto`

继续继承 `ZipperProto`，保留正常的玩家建筑语义、成本、可建造性和架高入口。

它从 Connector 复用：

- `EntityLayout`；
- 四向动态传送带端口布局；
- `LayoutEntityProto.Gfx` 图形配置；
- 原版 Connector 菜单图标路径。

它**不继承 `MiniZipperProto`**，也不使用 Connector 的自动节点放置语义。

### `MeteredGateHeightPolicy`

负责 Metered Gate 独立的高度范围与边界执行。它不从 Balancer 或 Connector 读取 `CanBeElevated`，也不依赖 Connector 的 `PlacementHeightRange` 作为策略来源。

### `MeteredGateEntity`

真正的物流状态机，负责：

- 周期推进；
- 配额刷新与扣减；
- 单件缓冲；
- 输入接收；
- 输出轮询；
- 参数修改；
- 保存、载入与复制配置。

### `MeteredGateInspector`

只负责显示和调用实体公开方法。它不保存物流状态，也不直接修改实体私有字段。

## 3. 原型组合原则

### 3.1 为什么不再使用 `sourceBalancer.CanBeElevated`

Balancer 的架高能力属于 Balancer 自己的建筑契约。Metered Gate 只是借用其建造成本，不应把 Balancer 的放置行为作为自身语义的一部分。

因此 `sourceBalancer` 只用于构造：

```text
EntityCosts(
    sourceBalancer.Costs.BaseConstructionCost,
    ...
)
```

### 3.2 为什么不继承 Connector 的放置逻辑

Flat Connector 是传送带建造流程生成的内部节点，不是普通玩家独立放置建筑。直接继承或模拟 `MiniZipperProto` 会带入隐藏、搜索、成本、预览和自动节点等副作用。

因此 `0.2.0` 只把 Connector 当作静态模板：

```text
Connector -> Layout + ports + graphics + icon
```

而不是：

```text
Connector -> building behavior
```

### 3.3 Metered Gate 自己声明可架高

`MeteredGateProto` 仍调用 `ZipperProto` 构造函数，并将可架高开关显式设为 `true`。这个布尔值只负责开启普通玩家建筑的升降入口；最高和最低高度由独立策略约束。

## 4. 独立高度限制

### 4.1 允许范围

允许高度定义为：

```text
[0, TransportPillarProto.MAX_PILLAR_HEIGHT - 1]
```

该范围来自运输支柱的全局承载能力，而不是 Connector 原型的放置语义。

### 4.2 为什么仅设置范围仍不够

游戏的普通 `LayoutEntityPreview` 在到达允许范围边界后仍可能走一条“继续上下移动”的后备分支；Shift 快速升降还可能一次跨越多个高度单位。因此只写入 `m_allowedHeightRange` 不能保证最终光标高度一定合法。

`0.2.0` 使用四个局部 Harmony 补丁共同完成限制。

### 4.3 `SetLayoutEntityToPlace` 补丁

开始放置建筑后：

1. 判断当前原型是否为 `MeteredGateProto`；
2. 在 `ConditionalWeakTable` 中记录该 placer 是否处于 Metered Gate 放置状态；
3. 将 placer 私有的允许高度范围替换为自定义范围；
4. 立即夹紧当前 `TerrainCursor.RelativeHeight`。

切换到其他建筑时，激活状态会更新为 `false`，不会把 Metered Gate 的限制泄漏给其他建筑。

### 4.4 `CanMoveUpDownIfValid` 补丁

当预览原型是 `MeteredGateProto` 时，将结果设为 `false`，关闭普通建筑在边界处继续移动的后备分支。

该补丁只按原型类型筛选，不改变其他建筑的预览行为。

### 4.5 `raiseEntity` 与 `lowerEntity` 补丁

原升降方法执行后再次调用硬夹紧：

```text
finalHeight = Clamp(currentHeight, allowedRange)
```

这一步专门处理 Shift 快速升降从合法范围内部直接跨过上限或下限的情况。

### 4.6 状态存储

`ConditionalWeakTable<StaticEntityMassPlacer, PlacerState>` 用来按放置器实例保存激活状态：

- 不向游戏对象添加字段；
- 放置器被回收时状态可随之释放；
- 不使用一个容易污染其他场景的全局布尔变量。

## 5. 图形与菜单图标复用

### 5.1 图形复制

`MeteredGateProto` 对 Connector 的 `LayoutEntityProto.Gfx` 做浅复制，而不是直接共享同一个可变对象。

复制后清空内部 `m_proto` 所有者引用，使新的 Gfx 在 Metered Gate 初始化过程中重新绑定到自己的原型。

### 5.2 图标路径

如果 Connector 已完成初始化，则直接读取：

```text
sourceConnector.IconPath
```

若路径为空，则按游戏生成图标的路径规则构造 Connector 自己的资源路径。

复制对象随后通过反射写入：

- `<IconPath>k__BackingField`；
- `IconIsCustom = true`。

`IconIsCustom` 在当前 API 中是 `public readonly` 字段，不能在普通 C# 代码中直接赋值，因此需要反射。

设置为自定义图标的目的，是阻止游戏在初始化 Metered Gate 时按 `MeteredGate_Entity` 重写出一个并不存在的生成图标路径。

### 5.3 版本耦合

图标实现依赖 `LayoutEntityProto.Gfx` 的内部字段名称。游戏更新后如果字段名或初始化流程变化，应首先检查这里，而不是修改物流实体。

## 6. 周期与配额状态机

### 6.1 初始状态

新建筑初始化为：

```text
buffer = empty
remainingQuota = 0
cycleElapsed = 0
```

因此建筑建成后必须先等待一个完整周期，才获得第一次放行配额。

### 6.2 时间来源

周期使用游戏原生 `Mafi.Duration`：

```text
cycleDuration = Duration.FromSec(cycleSeconds)
cycleElapsed += Duration.OneTick
```

这意味着：

- 全局暂停时模拟不推进；
- 游戏加速时周期随模拟时间加速；
- 单独暂停建筑时 `SimUpdate()` 直接返回，周期与物流同时冻结；
- 不使用现实时间、`DateTime` 或 `Stopwatch`。

### 6.3 周期刷新

跨过周期边界时：

```text
cycleElapsed = cycleElapsed mod cycleDuration
remainingQuota = itemsPerCycle
```

关键是**赋值**而不是累加：

```text
remainingQuota = itemsPerCycle
```

而不是：

```text
remainingQuota += itemsPerCycle
```

所以未使用额度不会积累成之后的集中爆发。

## 7. 输入接收与单件缓冲

上游通过 `ReceiveAsMuchAsFromPort(...)` 提供货物。以下任一条件成立时，整批拒收：

- 建筑暂停或禁用；
- 提供量为空；
- 内部已有缓冲物品；
- 当前剩余配额为零。

实际接收量为：

```text
accepted = min(offered, 1, remainingQuota)
```

因此内部逻辑容量严格为一个单位，即使上游一次提供多件也只接收一件。

配额在接收时立即扣减：

```text
buffer = accepted item
remainingQuota -= accepted
```

此时货物已经离开上游，所以即使所有输出堵塞，也不会继续从上游预取第二件。

## 8. 输出路由

`SimUpdate()` 在推进周期后尝试发送缓冲物品。

若存在多个输出，则从 `m_nextOutputIndex` 开始轮询：

1. 顺序尝试每个输出；
2. 第一个成功接收物品的输出完成本次发送；
3. 下次从该输出的下一个位置开始；
4. 若所有输出都堵塞，则保留缓冲物品。

这是简单 round-robin，不实现原版 Balancer 的：

- 输入优先级；
- 输出优先级；
- 均匀分配控制。

## 9. 参数修改语义

### 修改周期长度

周期长度发生变化时：

```text
cycleElapsed = 0
remainingQuota = 0
```

必须重新等待一个完整周期，避免通过修改参数免费获得配额。

### 修改每周期数量

- 降低设定值时，当前剩余配额会立即被压低到新上限；
- 提高设定值时，不立即补发额度，等下一周期刷新。

### 手动重启周期

Inspector 的重启按钮执行：

```text
cycleElapsed = 0
remainingQuota = 0
```

它不会删除内部已经缓冲的货物。

## 10. Inspector

Inspector 包含三个区域：

1. 周期设置、进度条和下次刷新倒计时；
2. 每周期数量、剩余配额和配额进度条；
3. 当前状态。

按钮只调用实体公开方法：

- `AdjustCycleSeconds(...)`；
- `AdjustItemsPerCycle(...)`；
- `RestartCycle()`。

`UiUpdateTrigger` 用作观察触发器。它是运行时 UI 辅助值，不写入存档。

## 11. 保存、载入与复制

### 11.1 实体存档

`SaveVersion` 保持为 `1`。序列化顺序为：

1. 基类数据；
2. 自定义存档版本；
3. 缓冲物品；
4. 剩余配额；
5. 当前周期相位；
6. 周期秒数；
7. 每周期数量；
8. 输出轮询位置。

反序列化必须保持完全相同的字段顺序。载入后还会对配额、周期相位和配置范围做防御性夹紧。

### 11.2 复制与蓝图

复制配置只包含：

- `MeteredGate.CycleSeconds`；
- `MeteredGate.ItemsPerCycle`。

不会复制：

- 缓冲物品；
- 当前周期相位；
- 当前剩余配额；
- 输出轮询位置。

应用复制配置后，建筑从关闭的新周期开始。

### 11.3 0.1.0 兼容性

`0.2.0` 保持以下稳定标识不变：

- 模组 ID：`MeteredGate`；
- 主入口：`MeteredGate.MeteredGateMod`；
- 原型 ID：`MeteredGate_Entity`；
- 实体类型和 `SaveVersion = 1`；
- 复制配置键；
- `config.json` 键。

因此旧存档中的 Metered Gate 应继续映射到同一原型和实体格式。升级前仍建议备份存档。

## 12. 运行时依赖与加载顺序

`0.2.0` 使用 `Lib.Harmony 2.4.2`。发行目录必须同时包含：

```text
0Harmony.dll
MeteredGate.dll
```

`manifest.json` 中 `primary_dlls` 的顺序为：

```text
0Harmony.dll
MeteredGate.dll
```

高度补丁通过固定 Harmony ID 安装和卸载，只处理本模组自己的 patch owner。

## 13. 维护边界与已知风险

当前版本只验证到 Captain of Industry `0.8.6c`。以下部分与游戏内部 API 耦合较强：

- `StaticEntityMassPlacer` 的私有高度范围字段；
- `raiseEntity`、`lowerEntity` 方法名称；
- `LayoutEntityPreview.CanMoveUpDownIfValid`；
- `LayoutEntityProto.Gfx` 的 owner、图标路径和只读图标标志字段。

游戏升级后若出现问题，应分层排查：

1. 建筑无法加载：检查 manifest、DLL 顺序和 Harmony；
2. 建筑能加载但高度越界：检查 `MeteredGateHeightPolicy` 的 patch 目标；
3. 高度正常但图标错误：检查 `MeteredGateProto` 的 Gfx 反射字段；
4. 物流或存档异常：再检查 `MeteredGateEntity`。

不要通过重新继承 `MiniZipperProto` 来修复高度问题，因为那会重新引入 Connector 内部节点语义和相关副作用。

## 14. 发布前回归测试

正式发布前至少验证：

- 从 `0.1.0` 存档载入已有建筑；
- 新建建筑等待完整周期后首次开放配额；
- 未使用配额在新周期被重置而非累加；
- 输出堵塞时内部最多保留一件；
- 多输出轮询顺序正常；
- 普通升降在上下边界停止；
- Shift 快速升降不会越界；
- 切换到其他建筑后高度补丁不影响其他原型；
- 菜单显示原版 Connector 图标；
- 保存、载入、复制和蓝图均保持预期语义；
- 发行包同时包含 `0Harmony.dll` 与 `MeteredGate.dll`。
